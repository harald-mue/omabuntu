## Conditional original-model editing prerequisite (plan 134)

The frame now exposes `moveWidget(move)` and `removeWidget(from)` using the
unchanged original BarModel operations, including their region/index/ID checks.
Tray nesting and unknown Component IDs remain excluded. A missing editor,
no-op, stale ID or rejected submission leaves the source layout untouched.

The optional shared Appearance editor submits `bar-layout-edit` with detached
`expected` and `layout` objects. Both must satisfy the existing closed
five-section registry. The backend compares the expected semantic layout before
allocation and again inside the existing cooperating-writer preference lock.
A stale request returns an explicit failed conflict result with fresh state;
a no-op creates no state file. Unrelated clock/tray edits do not create false
conflicts. Committed edits retain exact-byte/mode/absence rollback, including
receipt-failure recovery and later-drift refusal.

The adapter projects only a matching pending chain. After failure it drops
dependent conditional edits, retains independent preference requests and, for
unknown results, schedules one additional read-only state refresh rather than
replaying a write. Conflict notices survive unrelated successful responses until
a new layout attempt. Whole-layout `bar-layout` replacement remains an explicit,
unconditional administrative route, not the guarded gesture write path.

Two additional contained cases exercise guarded original-model move/removal
with retained instance state, and instantiate the actual Appearance adapter to
verify its bindings/conflict recovery without starting its helper Process. That
case requires exactly its expected conflict warning; unrelated warnings still
fail the suite.

The conditional prerequisite alone did not add mouse UI. Original pointer and
ghost/poof source is now restored below; live activation and native input/focus
acceptance are still outstanding.
Guarded removal is optimistic: a failed removal can reconstruct the widget when
the layout is restored; exact file rollback is not a promise to retain transient
widget state after a rejected removal. The semantic guard does not detect ABA
revisions or prevent an uncooperative external write racing after its locked
check. Native/pixel/session acceptance is not claimed.
