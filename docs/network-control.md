# Network control port

## Scope

The live network button is no longer the read-only status popup. It stages the
original Omarchy connection surface: icon button, connection hero, station
header and Wi-Fi list, including the original network row and inline passphrase
field. `NetworkControlView.qml` is generated by `tools/network_frontend.py`
(`network-control-frontend-v1`) from the unchanged `network/Panel.qml` parent.
It is not a second hand-written layout. The previous status view remains only
as a regression fixture; see [network status port](network-status-port.md).

User actions on a visible row use Quickshell's NetworkManager backend:

- known or open networks call `connect()`
- a protected unknown PSK/SAE network opens the original passphrase field and
  then calls `connectWithPsk()`; the typed value is cleared from the QML
  property immediately after that call
- the connected row calls `disconnect()` on that same SSID
- a saved, disconnected row can be forgotten; the row snapshot is rebuilt on
  completion without closing the panel. A still-visible access point remains
  under Other Networks rather than disappearing from the scan results
- the hero switch sets `Networking.wifiEnabled`
- opening the panel enables the station scanner after the original 100ms
  deferral and releases it on close; a manual refresh uses the same path

A stale row that no longer resolves does nothing. It cannot disconnect a
different network that happens to be connected. Wrong-password and missing-secret
results reuse the original model text and can reopen the passphrase field.
The 30-second action timeout only clears a stuck busy state. It does not stop
the bar.

Action success and failure schedule a list rebuild for the next Qt event turn:
replacing list data synchronously can destroy the delegate whose signal handler
is still running. Selection is clamped after list changes, password editing
tracks its SSID, and dismissing the editor restores keyboard focus. Opening and
asynchronous status updates align the DNS/band keyboard indices. Portal arrival
and departure also move the cursor to a valid section.

After the 100ms scanner deferral, a 1500ms completion timer rebuilds snapshots
even when only properties of existing network objects changed. Closing cancels
both timers and clears the scan indicator. These are operation timers, not a
lifetime limit on the bar.

When native Wi-Fi strength is unavailable, a conditional 1500ms poll calls the
Ubuntu helper's read-only `signal` operation. It reads the in-use AP from
`nmcli --rescan no`, without scanning or reading secrets, including while the
panel is closed. Replies are checked against the Wi-Fi interface and a link
change generation; stale replies cannot overwrite a new link's reading. The
poll stops when native strength is available or Wi-Fi is disconnected.

## Ubuntu actions for the previously excluded routes

The original captive-portal, band and DNS sections are staged. Ethernet and VPN
profile rows are not in Omarchy's network panel; they list saved NetworkManager
profiles of those two types. QR and the speed test stay inside this panel
instead of summoning the separate Omarchy plugins.

`tools/network_nm.py` is the only command the panel runs, and only after a
click. The bar passes its path in `OMABUNTU_NETWORK_HELPER`. It uses
NetworkManager on the active connection:

- DNS choices are DHCP, Cloudflare, Google and a custom address list. The
  change is written to that one profile and reapplied. If reapply fails, the
  previous DNS values are put back. Omarchy instead rewrites every Wi-Fi and
  Ethernet profile and a global NetworkManager file, which needs sudo. This
  port does not.
- Band choices are Automatic, 2.4, 5 and 6 GHz. A pin reconnects the active
  Wi-Fi profile and restores the previous band if the radio does not return.
  A band the network is not advertising is not offered.
- The captive-portal button opens `http://connectivity-check.ubuntu.com/`
  with `xdg-open` and closes the panel. It does not open
  `http://ping.archlinux.org/nm-check.txt`. While access is restricted, the
  panel asks NetworkManager to recheck every 10 seconds.
- The QR button reads the saved Wi-Fi secret inside the helper and draws only
  the module matrix. The passphrase is not printed, logged, or shown as text.
  Enterprise Wi-Fi is refused. The encoder is Project Nayuki's MIT-licensed
  `tools/qrcodegen.py`.
- The speed-test button runs one HTTPS download and one HTTPS upload against
  Cloudflare's public speed endpoints, each capped at eight seconds. It does
  not start Omarchy's unbounded parallel Fast.com workers.
- Ethernet and VPN buttons connect or disconnect an existing profile by UUID.
  They cannot select a Wi-Fi profile, create a profile, or change certificates,
  routes, the firewall, or a proxy. Tailscale and NordVPN are not installed.

## Still absent

- `omarchy-*` helpers, shell scripts launched by the panel, and new 802.1X
  profile creation
- reading `nmSettings` or printing a passphrase
- the original transfer, ping and gateway grid
- firewall, certificate and proxy editing

An unsaved enterprise (802.1X) row is refused in English and does not create a
profile. A profile NetworkManager already knows can still be activated with
`connect()` when the user selects that row.

The hero detail shows the device address reported by Quickshell instead of the
original helper's link speed. Section headers and empty status lines no longer
bind `height` to their own `implicitHeight`; Qt 6.10 reports that as a binding
loop, and visibility already removes them from the column.

## Validation

316 Python contracts pass without starting Qt. The Wi-Fi suite is:

```sh
python3 tools/check_tray_port.py --suite wifi --run --build-dir work/builds/<build-id>
```

Eleven isolated cases cover direct connect, one passphrase delivery, enterprise
refusal plus saved-profile activation, disconnect/forget, radio toggle, a stale
SSID, asynchronous action/list refresh, selection/editor/portal/settings focus,
scan completion with unchanged object membership, signal fallback and stale
reply rejection, and the deliberate exit 42. The fixture replaces `Quickshell.Networking`
and native `KeyboardPanel` ownership only in the private copy. It uses a normal
Qt `Window` so the deferred scanner timer can run offscreen. No host
NetworkManager, DBus, pointer or real passphrase is used. The passphrase
fixture value is not written to the success log.
