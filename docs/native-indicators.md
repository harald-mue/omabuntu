## One shared native owner

IndicatorState.qml owns both facades for every output. It starts bounded helper
queries only when the optional widget is selected in a loaded layout and the bar
is not hidden. Fixed status fields refresh every eight seconds, on explicit UI
refresh, and after an action. This repeating status refresh is not a component
expiry, timed diagnostic wrapper, autostart, supervisor or native daemon launch.
The component retains the approved bar's session lifetime. External state can
therefore be visually stale until refresh; a setter always revalidates separately.

Only the installed helper beside menu_model.py is addressed, via /usr/bin/python3.
Requests use bounded JSON stdin, not shell interpolation. Invalid/missing/late
old-scope output revokes known state. No setter is queued: busy owners refuse it.
The 24-second request watchdog bounds an individual RPC, not the component; an
interrupted setter stays uncertain/pending. Hiding changes the provider scope and
ignores late responses, but cannot undo a native action already issued.

## Closed native contracts

- **DND:** exact installed SwayNC upstream version 0.12.4 (Debian revision
  allowed), fixed root-owned, non-setuid busctl; canonical existing user bus only,
  --auto-start=no, no target well-known activation/claim. Connecting to the
  canonical user bus itself is a separate socket-activation risk, explicitly
  granted as described below; auto-start=no is not an atomic no-activation promise
  for that transport. Existing SwayNC must own both
  org.erikreider.swaync and org.freedesktop.Notifications through the same unique
  destination. Bus GUID, same-user PID/start, installed executable dev/inode and
  exact GetDnd/SetDnd introspection signatures fence the action key. Only GetDnd
  and an explicit SetDnd(boolean) are used. DND belongs to that shared user-bus
  notification owner, not an isolated per-output/per-Hyprland preference; it may
  affect notifications from other sessions using the same owner. The reviewed
  service binds its boolean to its **own** org.erikreider.swaync dnd-state GSettings
  key: a user click can persist that application preference through SwayNC. This
  is not a GNOME global DND write, temporary-only flag or raw dconf-file backup.
  Critical/bypass notifications follow SwayNC's existing policy. A GNOME-owned
  notification name is refused rather than changed. No ToggleDnd, Notify, notification
  body/count/inhibitor, CSS/config reload or GNOME global preference is invoked.
- **Nightlight:** only the exact current Hyprland instance's Hyprsunset socket;
  no fallback to another instance or implicit controller launch. A bounded exact
  dpkg-query requires installed upstream version 0.4.0 (Debian revision allowed).
  Before connecting, select only the exact listening UNIX-stream endpoint and
  its same-user root-binary Hyprsunset PID/start/owned socket FD. Missing, ambiguous
  or foreign listeners are unknown and are not contacted. Linux O_PATH pins the
  filesystem endpoint; connect uses /proc/self/fd, then SO_PEERCRED/executable and
  path/inode checks bind it to the reviewed existing process. A replaced pathname
  cannot silently redirect the connection to a new listener. Bounded /proc reads
  retain only this target's proof: no argv, environ, other FD paths or peer inventory.
  Four read requests obtain identity get, temperature, gamma, identity get. Only
  identity true/false is written. Kelvin, gamma, config files and scheduled profiles
  are never set/reset. Active means the controller's identity flag is false, not
  a physical warm-colour measurement. Automatic profile transitions remain the
  existing controller's policy and can supersede a manual identity choice.

Version-appropriate Hyprsunset v0.4.0 official source was reviewed privately in
Plan 148. SwayNC v0.12.4's licensed source/API and own GSettings schema were also
reviewed privately, with pinned tree/blob/hash evidence; no SwayNC/Hyprsunset code
is imported into the runtime. Bare identity changes state; profile can request a matrix update. Neither
is used as a getter. The daemon's stream protocol is not atomic/framed CAS:
fixed tiny commands, half-close/EOF, bounded parsing and readback do not promise
atomic delivery, all-output colour effect, perfect ownership isolation against
hostile same-UID manipulation, unobserved ABA detection or native acceptance.
No kernel/netlink probe, module load, privileged operation or service start is used.

Each child has a maximum three-second transport window and 64KiB combined output
bound (stderr is discarded). One helper's native budget is eighteen seconds;
child cleanup is separately bounded. Socket replies are capped at 4KiB, /proc
input and PID/FD scans are finite, and missing/unsupported/timeout/partial status
is distinguished. Only known booleans and opaque proof keys leave inspection;
private native identities/settings stay in receipts, not labels or project files.

## Explicit actions, uncertainty and recovery

indicator_state.py requires --allow-existing-owner-queries for inspect/set and
--apply-user-indicator additionally for a write. DND bus connections additionally
require --allow-session-bus-connection-risk, even for a getter. Without it no bus
probe/client is started and DND is unknown (nightlight can still be read). A
canonical bus socket may activate its user-bus transport if that transport exits;
there is no atomic no-activation guarantee. Target application auto-start remains
disabled. Selecting Show Status Indicators is explicit query/transport consent;
its menu description names this risk. Deployment/visibility approval must include
it; merely shipping these files does not grant it. A provider-scoped SHA-256 key
binds kind, observed state, native generation and (for colour) Kelvin/gamma.
It is a stale-request fence, not an authentication token/security boundary.
The helper obtains a fresh snapshot, rejects drift, serializes actions without
queueing, fsyncs a private before/prepared receipt, revalidates again, issues one
explicit setter and reads back. No retry, compensating toggle or hardcoded reset.
Protocols do not offer atomic compare-and-swap; changes after checks can remain
uncertain even when native calls completed successfully.

Receipts live under OMABUNTU_STATE_HOME/native-indicators (otherwise the usual
XDG state omabuntu directory), with 0700 directory/0600 files, link/mode/schema
checks, atomic replacement and fsync. A prepared/uncertain/corrupt receipt blocks
further indicator writes globally; status reads do not clear it. A crash after
preparation never causes a setter replay on startup. A finite history bound fails
closed instead of silently expiring/deleting backups. Normal component lifetime
is unrelated to these storage/request bounds.

After privately reviewing a pending receipt and fresh status, an explicit
acknowledgement may use:

```sh
python3 indicator_state.py acknowledge --receipt 00000001 --acknowledge-uncertain
```

Use the packaged helper's actual path; the ID above is illustrative. This command
performs **no native action** and records restored:false. It is not recovery or
acceptance. Do not automatically acknowledge, delete or edit corrupt evidence.

For a **confirmed** action, returning to the previous boolean is another explicit
set request, with receipt.scope, receipt.kind, receipt.after_key as expected and
receipt.before.active as desired, plus query/write and, for DND, bus-connection
risk grants. The same action
preflight rejects subsequent native-state/owner/Kelvin/gamma drift instead of
retargeting recovery. This creates a new receipt and restores only the boolean;
it does not reconstruct unrelated configuration, SwayNC key unset-vs-explicit
inheritance, or scheduled transitions. Native API value recovery is not a
byte-exact dconf/inheritance rollback; no global dconf snapshot is collected.
Uncertain/interrupted actions have no trusted after_key: inspect/review them first,
acknowledge without claiming restoration if appropriate, and separately approve
any fresh corrective action. Hiding/uninstalling the UI never performs recovery.
