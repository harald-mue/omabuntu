# Original notification service port

## Goal and evidence

Port the original Omarchy v4.5.0 notification component closure at
`ac2690cd7be4f47e4a255f5e2e78d904d436b068` with narrow Ubuntu adapters for actions,
private persistence and exclusive service ownership. Bind the existing original
DND indicator to the new owner. Preserve the original deck/card interaction and
visual hierarchy; do not substitute an authored replacement panel. Compare the
hash-verified sources and upstream documentation from Plan 172 against current
Quickshell, shared frame/theme and SwayNC DND boundaries. Preserve the Omapager
MIT attribution and record every imported source and derivation.

## Current gaps and proposed shape

The ordinary shell has no notification service and its DND adapter addresses
SwayNC. Add sealed original notification sources and explicit shared dependencies,
a fail-closed startup admission gate, private bounded state backend and reviewed
Ubuntu action boundary. A notification-enabled shell must refuse a pre-existing
notification owner rather than request its name or replace it. The ordinary
source default must not claim the notification name until a separately approved
migration grants that role. Validate original models and real QML against
synthetic providers in device-free containment. Keep deployment separate.

## Safety and explicit exclusions

Back up affected project paths and record hashes/modes before changes. No live
notifications, notification-history/body collection, SwayNC stop/reload, DND
setter, package installation, installed release change, desktop restart, shortcut,
autostart, service activation, debugger interruption or commit. No upstream
installers, migrations, arbitrary helper PATH or shell command execution. Preserve
GNOME and the existing user bus notification owner. Do not implement an automatic
fallback that races two notification servers. Native popup/pixel/security/crash
acceptance and the reversible live migration remain separate approval gates.

## Implemented inactive source candidate

Ten original files are imported unchanged under the recorded vendor path. The
original Toast/DeedButton and seven JS modules are staged byte-for-byte. The
service derivation changes only state preparation/location, closed action/helper
boundaries, IPC namespace and delayed server construction. The original deck,
scene, per-output surface, hover, mask, keyboard and arrival/departure source are
retained. No authored replacement toast surface or SwayNC theme was introduced.
The shared palette exposes original notification role defaults. Full shell.toml
layers, additional fonts/assets and locale catalogs remain excluded.

Private preparation refuses unsafe/malformed existing state without repairing,
migrating or printing it. Original bounded atomic persistence, transient handling
and code redaction remain. Standard sender actions and window routing remain;
command hints are narrowed to one validated external URL through the explicit
Ubuntu seam, never arbitrary commands or an Omarchy helper PATH. The shared DND
facade points to the original service only after admission; before that it keeps
the existing adapter. There is no automatic new-provider fallback on failure.

## Exclusive runtime and remaining host admission

The pinned runtime's notification singleton registers a watcher which retries
name acquisition after another owner exits. A shell-only preflight is racy and
QML destruction does not remove that singleton. This is why the source host's
deployment/runtime proofs default false, with no normal-manager, environment or
appearance producer. These booleans are a dormant integration contract, not a
completed artifact-verification or adversarial security mechanism.

The exact-source candidate patch removes the watcher, explicitly refuses queue/
replacement and fails immediately on a registration conflict or unavailable bus.
Plan 174 subsequently clean-built it in a separate network-free variant and
passed all six actual native private-bus checks, including an unpatched negative
control. Full artifact/checker hashes bind the eligibility receipt. The baseline
stage is unchanged and only the candidate executable differs.

Plan 175 adds an explicitly selected, inactive review-package path and an offline
capability producer/verifier. It preserves the exact patch and private evidence,
checks the relocated runtime and sealed original source closure, and always
returns deployment approval false. This does not yet supply the host's deployment
role. Do not enable the host manually or call this deployment-ready. Native
surface/input acceptance and the reviewed single-owner migration remain open;
stopping SwayNC is not authorized.
