# Install the original-shell audio and layout expansion locally

## Goal and evidence

Apply the user's request for a local installation of the completed Plan 134
source slices: playback streams, shared keyed layout, conditional layout edits,
original horizontal pointer/ghost/removal behavior and independent default-layout
recovery. Compare the verified installed release and current sealed preview
sources, helper bytes, menu definitions and derived provenance. The original
Omarchy baseline remains v4.5.0 commit
ac2690cd7be4f47e4a255f5e2e78d904d436b068; no new import is needed.

## Current gaps and proposed shape

The selected release predates these source slices. Prepare an immutable private
derivative of that release with exactly the ten changed/added sealed shell files,
the appearance backend and new bar-layout helper, the command-menu definitions
and local provenance. Retain the native runtime, manager, original assets,
remaining helpers, update contract and installed configuration bytes. Use the
existing transactional updater, its drift checks and rollback journals. Override
start only to prevent wallpaper restoration during both update and recovery.
Preserve the existing explicit session-lifetime grant without an expiry timer.

## Safety and exclusions

Before applying, record selectors and back up every affected existing file with
existence, SHA-256 and mode, including launcher, process record and current
preferences. Record absent candidate destinations and preserve prior immutable
releases. Check runtime preflight, units and isolated frame/audio fixtures before
switching. Restart only the identity-verified owned bar. Do not change packages,
sources, services, autostart, bindings, compositor configuration, wallpaper,
GNOME/global window-control preferences, user applications or login state.
No privilege, security changes, lock/idle/suspend activation, commits or remote
publication. Installation is not native visual/input/security acceptance and does
not complete the remaining Plan 134 A–E areas.

## Outcome and rollback

The transactional local update completed with exactly fourteen manifested paths
changed: ten sealed shell files, two helpers, menu definitions and provenance.
The existing native runtime, manager and all remaining manifested files are
unchanged. All 1,382 unit tests, twenty-four isolated frame cases, twelve isolated
audio cases and runtime preflight passed before application.

Only the identity-verified owned bar restarted, with a session-lifetime grant and
no wallpaper restoration. Installed integrity, startup markers and independent
Restore Default Layout menu action were verified. Bar, World Clock, dock and old
window-control preference existence/bytes/modes and the shared global button
setting remain unchanged. No pending update/deployment journals remain. Previous
and earlier immutable fallback releases still verify.

Private backups, exact changes, candidate identity, update journal and checks
are retained under work/original-shell-installation-135/. The standard previous
selector now points to the pre-update release. A requested rollback can use the
existing transactional rollback review/apply path with the same bar-only start
override, restoring the prior selection without wallpaper restoration. Retain
all immutable releases and journals; do not remove preferences or restore old
preference backups over subsequent user edits. Rollback is a separate desktop
operation, not performed preemptively.

No packages, services, autostart, bindings, compositor configuration, wallpaper,
GNOME settings, applications or login state were changed. No commit/publication
was performed. Native interactive checks of stream controls and bar movement,
removal/recovery, focus, grab retention and visual/scaling/hotplug behavior are
still owner acceptance work. The remaining Plan 134 A–E areas are not completed.
