## Gap and proposed shape

The additional page currently supplies an extra visible/cursor entry even though
its native bridge defaults to ungranted. Add a fixed disabled capability boundary
in the controller and capability component: no visible entry, no capability rows,
no keyboard route, no forced page selection and no invocation through stale rows.
Retain normal output/input/stream controls, accepted height/scrollbar behavior,
labels, artwork and OSD. Leave dormant helper/recovery code and private receipts
intact; disabling this UI is not deleting or acknowledging recovery records.
Keep backend-only synthetic profile/recovery tests without presenting them as
available UI. Test the actual sealed popup with the disabled default.

## Safety and exclusions

Diagnose first and privately back up affected source/installation paths with
existence, hashes and modes. Refuse deployment over unresolved native audio or
installation transactions. No live audio queries with activation risk, native
profile/gain/mute/routing/default changes, monitor changes, packages, services,
permissions, bindings, session transitions, autostart, wallpaper, commit or push.
Restart only the owned session-lifetime bar; every normal/recovery start uses
`restore_background=False`. Installation/navigation must not grant optional audio
access. Preserve the normal typed controls and existing consent boundary: an
optional virtual-input fallback must not gain access implicitly. Synthetic and
contained QML checks are not live call/device/pointer/pixel/security acceptance.
